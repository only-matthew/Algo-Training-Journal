## F1：重做入口不是一次性操作

位置：`lib/form.mjs:350–382`，`onDateChange` 的 URL 更新约在 1259–1264 行；入口来自 `lib/problem-detail.mjs`。

复现：打开 `/submit/?date=<今天>&redo=<题目信息>`，等待自动生成一条重做草稿；刷新浏览器。表单先恢复草稿，再执行 `appendRedoProblem`，出现两条相同题号、不同记录 ID 的记录。再次刷新会继续追加，直到当日题数上限。保存时当日只校验记录 ID 唯一，因此这种重复不属于正常去重保护范围。

根因：`redo` 查询参数没有在成功消费后移除；恢复逻辑与命令执行逻辑叠加。影响是无意创建新尝试、放大题数与训练统计，且可能挤占 15 题额度。

建议：成功追加后用 `replaceState` 消费该参数，或为操作建立可恢复的一次性标识。保留用户主动记录同日多次尝试的能力。验收：首次进入一条，刷新仍一条；主动发起第二次重做才新增记录；失败和满额不应假装成功消费。

## F2：清单冲突提示的恢复路径不起作用

位置：`lib/my-list-ui.mjs:37–51`、`76–95`；`lib/application.mjs:99–110`；`src/app.js:189–191`。

复现：读取清单版本 r1，模拟其他页面已更新导致 PUT 返回 409。UI 提示“清单已在别处修改，请刷新后重试”；点击账号菜单中的站内“刷新”。训练档案重新加载，但 `/api/my-list` GET 次数仍是一次，旧 `current.revision` 与冲突提示不变。继续保存会再次使用旧版本。

浏览器整页重新加载可以恢复；本问题限定于站点自己提供的刷新按钮。也影响普通手动刷新时个人清单与训练档案数据不同步。

建议：档案页刷新同步重新读取清单及完成证据，或在冲突提示旁提供明确的清单重载操作。读取期间限制编辑并保护迟到请求；失败时保留输入。验收：外部更新后刷新可得到最新清单与 revision，随后保存正常。

## F3：AI 概括无条件覆盖较新的正文

位置：`src/app.js:88–97`，尤其 `desc.value = res.summary`。

复现：填写超过 20 字的描述，点击 AI 概括并挂起响应；在同一文本框修改正文；释放旧响应。新输入被直接替换为旧请求的概括，UI 仍提示“已生成概括”。该替换随后进入草稿保存流程。

根因：只禁用了概括按钮，正文仍可编辑；没有比较请求输入快照与当前内容。此问题是相同题块内的更新丢失，与存量 S1 的日期切换问题不同。

建议：保存请求时的文本与题块标识；返回时仅在正文未变化且仍属当前表单会话时自动应用，否则展示待应用预览。验收：未编辑时正常回填，期间编辑时保留用户文本，切换日期和删除题块后不影响新表单。

## C1：浏览器写入和日期读取缺少默认超时

位置：`lib/journal-api.js:14–32`，`loadDateLog`、`saveDateLog`、`saveDateLogV2`、`apiRequest('/api/my-list', ...)` 等调用。

检查生产函数发现，日期读取和清单 PUT 的 fetch 参数均无 `signal`。当前只有会话调用显式传入 4 秒超时，静态 JSON 层另有 10 秒超时；这些保护没有覆盖通用 API 客户端。连接迟迟不结束时，表单可能一直停在加载或提交中，相关恢复按钮也依赖请求结束。

本证据确认的是客户端没有应用层截止时间，不声称所有真实请求都会永久挂起，也没有测量生产网络超时。Worker 的上游超时无法完全解决客户端到 Worker 这一段连接迟滞。

建议：按读取、普通写入、附件上传设置合理截止时间并支持调用方取消。**写请求超时不能推断服务端未提交，也不能无条件自动重试**；需要提示重新读取确认，附件重试复用操作 ID。验收应同时覆盖超时恢复和“服务端已成功、客户端未收到回执”。

## D1：超纲语义同时存在两套互斥的验收

证据：

- `docs/PRODUCT.md:22` 与 `docs/DESIGN.md:12` 仍写“超纲只用于未完成、退出近期复习队列”。
- `docs/SPECIFICATION.md:60` 仍把 `deferred` 当作新表单的用户选择，并声称超纲约束有测试。
- 同一规格 §1.1 已明确 v8 使用 `masteryStatus=beyond_scope`，结果与复习安排分别表达事实，旧 deferred 的未完成约束从未实现。
- `e2e/journal.spec.mjs:413–465` 明确要求超纲自评保留 todo 和自选复习日期；新表单不再包含 deferred 选项，schema 也没有只允许 unfinished 的关联约束。

这里应判为**规格漂移**，不能仅凭旧产品段落修改代码，使其自动清掉用户的复习日期。按当前 v8 实现与已有回归统一文档；如果产品确实要求恢复限制，再单独确认产品语义和迁移方案。验收条款必须说明哪些是历史兼容，哪些是新写入契约。

## D2：冻结声明误覆盖生产复习调用

证据：`docs/SPECIFICATION.md:18`、`docs/CURRENT-STATE.md:28` 泛称 `/api/v2/me/*` 没有生产前端消费者且冻结；但规格接口表 §1.3 同时列出单题复习 PATCH。

实际调用链：`lib/renderer.mjs` 的复习操作 → `patchRecordReview` → `lib/journal-api.js` 的 `PATCH /api/v2/me/logs/dates/:date/records/:id`。现有浏览器回归也验证了这个请求。

建议：冻结声明精确限定到旧 training 工作台、计划及未接入的事件接口，明确排除现行日志复习 PATCH。避免后续维护者依据错误的“无人使用”说明删除或停止维护此接口。
