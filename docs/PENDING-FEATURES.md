# 待实现功能评审：区间训练与同日多次记录

2026-09-13 评审版。**状态：设计已修订，区间录入与同日多份正文尚未实现。** 活力 v2 的通用计分、跨平台统计和个人展示已完成，见 [VITALITY-V2.md](VITALITY-V2.md)。本文替代原 A–E 施工草案；未来实施仍须更新 SPECIFICATION.md 的接口契约与 Schema，不能把设计当成当前行为。

## 结论与冲突处理

两项需求合理：连续攻坚应该能记录实际投入，同日重做应该保留各自心得。题目数、训练日、尝试次数、活力必须分开。保持自主训练，不设打卡排名或逾期问责。

| 原设计问题 | 修订 |
| --- | --- |
| meta 再存 outcome，与事件投影冲突 | training 尝试事件为结果的唯一权威；solvedOn 从首次有效完成事件推导。 |
| 旧日志默认 independent | 历史结果保持 unknown，不生成独立完成证据。 |
| 未完成 30%/15% 混用，min(0.15×天数,0.15) 第一天就封顶 | 统一固定 15% 的首次部分额度，不按天加分，删除无效天数公式。 |
| 首次去重吞掉后续攻克 | 保存同题结算状态，先给 0.15B，独立完成再补 0.85B。v2 纯函数已支持，事件接入待做。 |
| 只校验单日最多一个 first | first 不能是客户端任意指定的计分开关；服务端按成员/subjectKey 跨日期检查，算法再次去重。 |
| legacy 索引按 subjectKey 合并 | 会丢同题多次正文引用。原始索引按完整 recordRef 保留，题目级聚合另做投影。 |
| “A+C 就能解决断 streak” | 必须接入区间并集、streak 和热力图；只加字段和分数无效。 |
| 起点限制在记录前 120 天，但完成日期可延到今天 | 限制实际确认区间的包含天数最多 120，不能绕过起点约束。 |
| 声称全库题号完整 | 有 11 条其他平台记录无题号。允许计分，但不能靠名称推断同题。 |

## 1. 数据和日期语义

建议在现有 attempt.recorded 事件增加可选 startedOn，沿用 performedOn 为本次确认的最后训练日。实际训练区间为 `[startedOn ?? performedOn, performedOn]`。事件继续引用 recordRef 和 subjectKey，不改变日志目录日期。

服务端验证：

- 两端都是真实 YYYY-MM-DD；`startedOn <= performedOn <= UTC+8 今天`。
- 包含首尾天数 `dayDiff(startedOn, performedOn)+1 <= 120`。
- 允许补录；日志正文日期与实际训练日期分开，不要求事件永远早于最初日志日期。
- 首次有效完成日期取 independent/hinted/editorial 的最早有效事件；unknown 不证明完成。
- 纠错、作废沿用 sequence 顺序投影；新增 startedOn 后，同步更新纠错字段、Schema 和幂等请求哈希。

交互默认单日。展开“连续训练区间”后明确显示“确认这几天都有训练”；区间有休息日时拆成多段。不能把“题目尚未做完”自动视作每天都在练。

“仍在攻坚”只覆盖到最近一次本人确认的 performedOn，页面刷新不能自动延伸到今天。延长区间需要新记录或显式纠错，否则不训练也能无限续 streak。

旧日志只展开记录当天，不补造区间和完成事实；事件区间与历史单日求并集，重叠天数不重复计。

## 2. 独立统计与结算

| 指标 | 口径 |
| --- | --- |
| 现有累计题数 | 本次保留原日志记录口径，不能偷偷把历史 165 改成去重题数。 |
| 不同题目数 | 另增 subjectKey 去重统计；题号未知只能按记录计，并说明不确定性。 |
| 训练日 | 本人确认区间与历史单日的并集；全队也取日期并集，不相加成员天数。 |
| 尝试次数 | 有效 attempt.recorded 事件数；纠错、作废、延期不增加次数，历史日志不伪造尝试。 |
| 活力 | 冻结同题首次有效 Rating/匹配基准 B，按有效结果额度补差额。 |

原草案同时要求“保留历史题数”和“同日多条不增加题数”，需要一次明确的口径迁移。建议开放多次记录时将既有累计题数明确命名“历史记录数”，并列新增“不同题目数”“尝试次数”；确定界面迁移后实施，不能用同一个无说明的数字混合两种定义。

未来接事件时按 performedOn、sequence 重放有效事件；缺少日内时间的历史日志仍用日初能力估计。先应用纠错/作废再计算，不能把纠错当额外一次高分训练。源事件 subjectKey 不能被日志题号编辑静默改写。

采用累计额度守恒：首日 0.15B，完成日补 0.85B，最终 B。不要保留首日部分分后又在完成日发全额。如果坚持“完成日显示 B”，必须单设结算展示视图，不能和每日增量混用。

复习可用于复习历史和证据卡，但不增加同题活力额度。未知题号补全、历史事件身份合并属于显式迁移操作，不能按题名自动合并。

## 3. 同日多份正文安全落库

当前 planLogChanges 按数组下标生成 N-desc.md / N-takeaway.md / N-solution.cpp，readLog 也按下标读。仅“保存前按 ID 排序”不够：删除中间项会移动下标，局部保存没读全正文就可能错配。

建议新增服务端管理的可选 fileIndex：

1. 旧记录读取用 `fileIndex ?? 数组下标`，保持原路径和永久 ID。
2. 增量保存读取同一快照的 meta，以记录 ID 找既有 fileIndex，禁止客户端重写槽位。
3. 新记录分配未占用槽位，旧记录不重排；删除只删除目标槽位，不重命名幸存正文。
4. 校验非负整数、单日槽位唯一；readLog、构建、导出、删除和全部写入入口同步理解 fileIndex。
5. meta 和正文同一 commit 写入。原始索引保留全部 recordRef，不按 subjectKey 折叠。

fileIndex 尚未实现。另一方案是 ID 命名正文，但需要新旧路径双读，不建议顺带迁移全库。

前端检测同题后提供“补充这条记录”“新增一次训练”：前者编辑指定 recordRef，后者创建独立记录 ID/attemptId。两者均不由前端决定首次分；无题号时不按题名强制合并。

## 4. 施工顺序

| 阶段 | 内容 | 完成条件 |
| --- | --- | --- |
| 0：契约 | 更新 SPECIFICATION.md 的事件日期、字段、题数迁移和正文槽位 | outcome 只有一个来源；旧记录未知；明确幂等语义 |
| A：保存基础 | Schema、Worker 条件写入/冲突处理、fileIndex 兼容、按 ID 更新 | 多页编辑不静默覆盖；删除中间项不造成正文错位 |
| B：结果与区间 | 事件加 startedOn，表单确认区间、补录和纠错 | 单日/跨日/未完成可保存，权限与日期边界通过 |
| C：统计投影 | 共享区间并集函数，接构建、streak、热力图、个人图表、导出 | 重叠日期不重复；未完成到完成只补差额 |
| D：同日多次 | 独立正文/事件/ID，同题提示和尝试列表 | 两份心得各自可读，不同题目数不增加 |

A 是 B/D 的保存基础；B+C 一起解决区间打卡。可先交付单日结果与投影，再开放区间，不能只做表单就算完成闭环。

## 5. 验收清单

- 旧日志零迁移可读，结果 unknown，永久链接不变。
- 9/1–9/5 为 5 天；重叠 9/3–9/6 最终 6 天，不是 9 天。
- 未完成记录确认到 9/5，9/6 不自动点亮；休息日不被续上。
- 首日未完成、完成日独立通过，最终 B，完成日只增加 0.85B。
- 复习、重复导入、幂等重放不增加同题额度；unknown 不冒充独立完成。
- 同日同题两条心得和代码各自可读，局部修改不波及另一条。
- 删除中间项后文件、ID、链接仍对应；过期版本保存被拒绝。
- 拒绝未来、逆序、包含 121 天；接受包含 120 天、跨月、闰日。
- 纠错/作废后区间、完成日、活力同步重算，不留双重分数。
- 热力图同时表达训练与活力：零活力训练日有描边/斜纹，tooltip 区分攻坚/完成/复习。
- Markdown/LaTeX 导出包含区间、结果及各次记录，LaTeX 实际编译通过。
