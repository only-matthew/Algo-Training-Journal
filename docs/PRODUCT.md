# 产品方案：队员自主的一站式算法训练平台

更新时间：2026-09-05。依据当前仓库源码审查；以下明确区分已有能力与拟开发功能，新功能尚未实施。

实现契约见 [技术规格 SPECIFICATION.md](SPECIFICATION.md)，包含数据结构、接口、并发控制、算法规则、迁移与验收矩阵。

### 2026-09-06 实现状态补充

“我的训练”已提供独立 `/training/` 页面、栏目切换、重复刷新及本人已发布历史日志的题数、最近训练与待复习入口。新增事件和历史日志分开展示，历史“已掌握”不推断为独立完成。实时接口或推荐失败时，历史记录仍可显示；历史数据来自最近一次成功发布，尚未替代规格中同快照的工作台聚合。

当前计划编辑、接受候选/换题和完整自动推荐尚未接通；推荐接口仍返回空候选。页面明确提示功能状态并提供学习路线入口。本次空白修复不代表下述个人日常训练闭环已全部完成。

## 定位与边界

服务对象只有队员。成员自主设定目标、自选训练、发起约赛、分享题解、互相帮助。不存在教练角色、教练确认、作业审批、训练考核或上级分配任务的流程。活动发起人只维护活动信息，不拥有修改他人训练结果或自评的权限。

核心流程：确定目标 → 选择今天的训练 → 去原 OJ 做题 → 记录结果 → 补题、复习与队友交流 → 调整下一次训练。

“一站式”意味着选题、记录、复习、比赛组织和经验沉淀有统一入口，数据能够互相关联。首期继续跳转原 OJ 提交代码，暂不建设自有评测机。

## 现状与缺口

| 环节 | 已经实现 | 升级缺口 |
| --- | --- | --- |
| 记录 | 登录、按日期保存、题面/心得/代码、稳定记录 ID、本地草稿 | 未区分独立完成、提示后完成、题解后完成和未完成；缺少尝试历史 |
| 学习 | 知识树、七阶段路线、节点题单、前置依赖、标签聚合 | 缺少围绕个人目标的下一步选择 |
| 首页 | 个人主页、筛选、热力图、统计 | 默认仍是全队总览，尚无个人今日训练清单 |
| 复习 | 到期队列、已掌握/顺延快捷操作、错题搜索 | 当前状态不能证明重做结果，缺少完整复习历史 |
| 能力建议 | 题单内外训练证据、五档状态、理由与置信度 | 主要依赖记录数、掌握标记和时间，未验证独立完成与难度 |
| 协作 | 同题聚合、共享日志、导出、QQ 机器人入口 | 缺少约赛、队伍参赛记录、补题清单和按题目关联的求助 |
| 写入 | 本人目录授权、一次保存生成 Git commit | 整日覆盖；展示依赖重新构建；需内容版本校验与保存进度反馈 |

源码依据：`index.html`、`lib/log-schema.mjs`、`lib/mastery.mjs`、`lib/renderer.mjs`、`lib/form.mjs`、`lib/journal-api.js`、`workers/oauth.mjs`。

需要先纠正的认识：

- 当前 `assessMastery` 在至少 5 条关联记录且至少 1 条标为已掌握时返回“较熟练／高置信度”。这不等于独立做出 5 道不同题，也没有验证难度和题型覆盖。
- 无记录只代表“暂无训练证据”，不能判断队员“未接触”该知识点；应调整显示语义并支持本人自评。
- 快捷复习免去了手动打开表单，但后台仍读取当天数据后整日 PUT。Git 分支冲突重试不能替代内容版本校验。
- 草稿当前按日期保存到同一个本地键，需要按账号隔离，避免共用浏览器切号时恢复错人的草稿。
- 当前内容公开读取。未来队内可见的讨论必须通过鉴权接口读取，不能写入公开仓库或静态产物后仅在页面隐藏。

## 页面组织

顶层建议为“今天 / 学习 / 复习 / 队伍 / 我的”。搜索与“记一题”作为全局入口，保留原有题目、标签和成员深链接。

| 入口 | 首屏内容 | 主要操作 |
| --- | --- | --- |
| 今天 | 本人清单、到期复习、待补比赛题、草稿 | 开始、换题、延后、快速记录 |
| 学习 | 当前节点、前置知识、精选题单，可展开完整知识树 | 选择方向、加入今日清单、收藏 |
| 复习 | 待重做题、上次卡点、历次复习结果 | 重做、记录结果、调整日期 |
| 队伍 | 自主约赛、共享题单、同题交流、专题覆盖 | 发起或参加活动、求助、分享 |
| 我的 | 自选目标、历史、自评、模板与统计 | 调整计划、管理平台账号、查看变化 |

未登录保留公开浏览，登录后默认进入“今天”。全队热力图与统计进入队伍视图，个人首页优先呈现能直接开始的训练。

## 第一批：个人日常训练闭环

### 今日训练台

首次只需选择当前专题与可用时间，例如 30/60/120 分钟，均可跳过；手动加题也能使用。

默认给少量候选，按“到期复习 → 自选待补题 → 当前专题巩固 → 进阶”排序。根据题目是否已做、前置节点和平台原有难度筛选，不强行折算跨平台难度。每题显示推荐原因、原题链接、已有训练状态。

允许换题、移除、延后与调整数量。可用时间是预算，不承诺准确预测耗时。缺少数据时说明原因，回退到自选专题的基础候选。已接受的清单保持稳定，刷新不会不断换题。

计划与日志分开保存：允许安排未来训练，现有日志仍禁止记录未来日期。验收目标：登录后一分钟内开始一道题；完成后关联日志并更新清单；普通推荐去重，明确的复习题允许重复。

### 快速记一题

默认只要求题目身份和结果，心得、代码、耗时与错误原因按需补充。保留整日编辑和原有记录链接。

新增“未完成／独立完成／提示后完成／题解后完成”，与复习状态分开保存。看题解后 AC 不自动等于掌握。缺少新字段的历史记录默认为未知，不能默认成独立完成。

区分三个概念：平台与题号标识同一道题；现有永久 ID 标识日志；每次训练尝试有自己的 ID。缺少题号的旧记录继续可读，不按题名强行合并。导入以来源提交 ID 等依据去重，重复同步不得重复创建事件。

验收目标：约半分钟完成必要记录；保存后本人立即看到已保存内容与发布状态；历史记录和导出兼容。

### 真正的重做与复习

开始重做时折叠旧题解和代码。完成后记录“独立做出／借助提示／仍未做出”、可选耗时与卡点，再建议下次复习日期。

先使用简单、可解释且可手动调整的间隔规则。延期仅调整日程，不计复习成功；自评“已掌握”与实际重做结果分别展示。

验收：能查看首次训练和各次重做；刷新后结果仍在；独立重做通过与延期分别统计。

### 能力卡

分别展示不同题目数、尝试次数、独立完成、提示依赖、最近训练时间、待复习情况和本人自评。结论可追溯至具体记录，历史字段缺失时降低证据充分程度。

先用“证据不足／已有练习／有独立完成证据／建议复习”等谨慎描述，不把题量直接包装成高置信度能力结论；积累重做数据后再校准规则。

本人随时修改自评并保留时间与备注。队友提供交流建议，不修改他人自评。系统建议、本人自评和原始训练事实分别保留。

## 第二批：自主组队训练与互助

任何队员可发起约赛，填写比赛链接、时间、参赛方式和目标，其他人自主报名。第一版手动关联成绩与题目，之后再评估平台导入。

区分个人参赛与小队参赛：小队 AC 不自动计为所有成员独立完成。可记录读题、想法、实现和调试贡献，但不据此排个人名次。即使没有 AC，比赛记录也能保存。

赛后每人自行加入补题项，记录卡点和改进，补题结果回流到个人日志和知识节点。验收覆盖发起、报名、参赛结果、生成个人补题项、完成补题全流程。

在现有同题记录上增加求助与讨论，答案默认折叠。显示“哪些队友记录过这题”，不自动把他们认定为专家或分配答疑。

共建专题题单、常见错误和算法模板。模板包含适用场景、复杂度、边界和验证题，关联日志并保留作者与修订。修改他人资料通过建议或明确的共同编辑授权。

团队覆盖用于寻找交流对象、约定训练方向，不设置能力总榜、强制打卡和逾期问责。

## 第三批：自动化与学习助手

- 在已有导入上完善账号设置、同步去重、结果纠正、失败说明与最后成功时间。
- QQ 机器人复用站内今日计划与复习数据；通知自行开启，可关闭并设置安静时段。
- AI 作为学习助手，提供分级提示、解法解释、错误归纳和基于记录的推荐说明。是否展开完整答案由用户决定。
- AI 输出与原记录区分，不能自动宣布掌握、修改自评或替队员完成复习。
- 当前 `bot/qq-message.mjs`、`bot/listen.mjs` 和 `workers/qq-bot.mjs` 仍含教练称呼或身份提示；实施时统一改为学习助手。本次方案审查没有修改机器人运行代码。

## 技术路线

首期沿用 Git 日志、静态展示和 Worker 写入，无需为新首页立即重写前端或迁移数据库。推荐规则独立为纯函数，按 UTC+8 当天在浏览器或 API 层计算；不能只在构建时计算，以免无新发布时到期状态失准。

按新增功能逐步拆分 `lib/renderer.mjs`，把今日计划、复习与题目视图独立组织，仍由 `lib/application.mjs` 协调。保留静态详情、检索、导出和原有链接。

| 新数据 | 内容 | 写入归属 |
| --- | --- | --- |
| 尝试/复习事件 | 关联题目与日志、结果、时间、提示使用、来源提交 ID | 本人 |
| 设置与计划 | 目标、专题、时间预算、选定题目、计划状态 | 本人 |
| 节点自评 | 节点 ID、自评、备注、时间 | 本人 |
| 比赛活动 | 时间、链接、参赛方式、状态 | 发起人维护活动，成员维护自己的报名和结果 |
| 讨论与资料 | 题目/节点关联、作者、正文、修订 | 作者或明确授权的共同编辑者 |

低频个人数据可先放独立成员目录文件；这是拟议扩展，现有 Worker 尚不支持。新增接口限制字段、路径与归属，不开放任意仓库写入。

讨论、报名、多端编辑若需要即时共享，再评估动态存储。迁移时逐类指定唯一权威来源：日志保留 Git，迁移实体以数据库为准，备份单向生成，不允许 Git 与数据库同时作为同一实体的可写主库。平台选型、接口限制与费用在实施前核实。

## 保存可靠性优先事项

1. 草稿按账号和日期隔离，切号同步清理内存状态；无法确认归属的旧草稿不能自动提交到当前账号。
2. 读取返回内容版本，保存/删除携带预期版本；不一致返回冲突，保留本地输入供合并或重新加载。分支重试后重新检查目标内容版本，不能重放旧覆盖。
3. 快捷复习改为按记录 ID 更新，服务端只合并本人目标字段，保留同日其他题；请求带幂等标识，重试不重复产生事件。
4. 保存返回内容与提交标识，本人先看到已保存结果；公开页面区分发布中、已发布和发布失败，不用固定等待时间假装更新成功。
5. 新字段贯穿 Schema、Worker、构建、导入和导出；兼容旧日志，不伪造独立完成或复习证据。

## 实施顺序与验收

以下为建议顺序，不是工期承诺。每批可独立交付。

| 阶段 | 交付 | 必须验证 |
| --- | --- | --- |
| A：可靠记录 | 草稿隔离、版本检查、保存反馈、单题入口与结果字段 | 多页不静默覆盖、切号不串草稿、本人写入权限、旧日志/导出兼容 |
| B：个人闭环 | 今日清单、换题/延期、重做历史、能力卡 | 选题到复习全流程、同题去重、跨天更新、历史字段缺失不误判 |
| C：队员协作 | 约赛、参赛结果、补题、同题求助 | 自愿报名、他人数据不被覆盖、小队结果不冒充个人完成、答案折叠 |
| D：自动化 | 同步、机器人提醒、资料库、可选 AI 提示 | 重试去重、失败恢复、通知可关、建议与事实分离 |

验证包括受影响单测、Schema 兼容、构建产物和关键浏览器流程。冲突、身份隔离和权限需专门测试，不能只检查按钮可见性。

## 衡量是否有用

观察开始训练所需时间、记录操作量、自选清单完成与调整、实际重做比例与独立通过情况、赛后补题完成、求助效果、资料复用，以及保存与草稿恢复可靠性。

缺失数据明确记为未知；主动延期不算违规；不以累计题量、打卡排名或未经验证的能力总分代替训练效果。
