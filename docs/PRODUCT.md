# 产品文档：一站式 ICPC 训练中心

更新时间：2026-08-28

## 产品愿景

Algo Training Journal 将从训练日志与题单浏览器，发展为队员日常使用的「一站式 ICPC 训练中心」。队员打开网站即可了解自己所处阶段、今天该练什么、哪些题需要复习，以及完成训练后的下一步。

核心闭环：

```text
能力画像 → 今日训练计划 → 做题与记录 → 复盘和复习 → 路线进度更新 → 下一次推荐
```

目标不是以题量给队员排名，而是用可解释的训练证据帮助每位队员补齐知识盲区、稳定提高解题能力，并帮助教练了解队伍整体训练覆盖。

## 用户与问题

### 队员

- 找题和选择训练方向成本高，不清楚下一道该做什么。
- 杂题、比赛题与题单题分散，难以形成完整能力认识。
- 题单未做会被误认为专题未学过；模拟、高精度等已有大量训练的专题尤其容易被误判。
- 错题与复习计划易被遗忘，缺乏「是否真正掌握」的反馈。

### 教练或队长

- 需要识别个人及团队的薄弱知识点，而非手工翻阅训练日志。
- 需要知道能力结论的数据依据，并能校准历史标签不完整带来的偏差。

## 产品原则

1. **训练记录是证据，不是分数。** 题量、题单完成、标签、难度、复习与自评共同构成判断。
2. **结论必须可解释。** 不简单宣称「未学习」或「已掌握」，而是同时展示证据和置信度。
3. **推荐服务当前目标。** 优先推荐到期复习、当前阶段和薄弱节点的题。
4. **保留人工校准。** 队员自评和教练确认可修正历史数据偏差，但不覆盖原始训练事实。
5. **先规则、后智能。** 第一阶段使用透明规则；AI 只解释或辅助建议，不作为唯一评分依据。

## 现有基础

项目已具备训练中心所需的核心数据和能力：

- 训练日志包含平台、题号、难度、标签、心得、代码、错题状态和复习日期。
- 题目详情、同题聚合、错题复习队列、个人主页与近期统计。
- 算法知识树、分阶段路线、知识点题单，以及题单与训练记录的自动匹配。
- 标签索引和题单外「相关训练记录」。
- Git 历史保证数据可追踪，Worker 限制成员只能写入自己的记录。

当前主要缺口是：题单进度被过度当作能力进度，题单外训练尚未系统参与能力评估。

## 核心能力：知识点掌握度

每个成员、每个知识点应有能力卡，而不是单一的题单完成率。

| 维度 | 回答的问题 | 主要证据 |
| --- | --- | --- |
| 题单进度 | 推荐题单完成了多少？ | 节点题单内的匹配题 |
| 训练覆盖度 | 是否有过足够相关练习？ | 标签匹配的全部训练记录，包括题单外题目 |
| 熟练度 | 是否能稳定解决该专题？ | 题量、难度、近期性、错题状态与复习结果 |
| 置信度 | 判断是否可靠？ | 标签完整度、证据数量、诊断结果与人工确认 |
| 建议动作 | 下一步做什么？ | 前置依赖、薄弱证据与复习计划 |

页面必须将「题单进度」和「关联训练」并列展示。例如：

```text
高精度
题单进度：0 / 12
关联训练：6 题（其中 2 题已掌握）
当前判断：有基础（中等置信度）
下一步：完成 1 道诊断题，确认边界处理能力
```

## 掌握度模型 v1

第一版不使用黑箱总分，而是输出可解释状态：`未接触`、`已接触`、`有基础`、`较熟练`、`建议复习`。状态是建议，不替代教练判断。

建议的初始规则：

- **未接触**：没有题单记录、关联训练、自评或教练确认。
- **已接触**：至少有 1 道关联训练，或队员自评为「有基础」。
- **有基础**：至少 3 道关联训练，且至少 1 道为非错题或已掌握；或通过节点诊断题。
- **较熟练**：至少 5 道关联训练，包含中等及以上难度题，且近期有成功记录或复习通过。
- **建议复习**：已有训练证据，但长期未练、存在逾期待复习题，或最近诊断失败。

规则应允许按节点类型调整：模拟、高精度等主题更重视题量与近期性；动态规划、网络流、数据结构等更重视难度、题型覆盖与前置依赖。

## 自评、教练确认与诊断题

日志无法完整还原历史能力，因此需要最小人工校准：

- 队员可选择 `未接触 / 有基础 / 熟练 / 需要复习`，并填写简短备注。
- 教练可确认或调整判断，保留确认人和时间。
- 当训练证据与自评冲突、或置信度低时，系统推荐 1～2 道诊断题。
- 诊断结果作为独立证据保存，不修改原始日志。

## 今日训练计划

首页应提供个人化的「今日训练」，默认按以下优先级选题：

1. 到期或逾期的复习题。
2. 当前阶段中覆盖不足、但前置依赖已满足的节点。
3. 有基础但置信度不足的节点诊断题。
4. 当前节点的巩固题或难度递进题。

每道推荐必须附带原因，例如「你已完成 4 道贪心题，但近期有 1 道待复习」或「高精度已有 6 条训练记录，建议用该题确认乘法与进位处理」。

## 分期路线图

### 第一阶段：训练证据可见化

目标：修正「题单未做 = 未学习」的错误认知，不改变现有日志格式。

- 构建期为每个节点、成员聚合题单内记录和题单外关联训练记录。
- 在知识树、阶段页和节点页展示题单进度、关联训练数及对应题目列表。
- 输出初始覆盖状态与置信度，不直接输出综合分数。
- 为聚合、标签匹配和展示补充单元测试与构建测试。

验收标准：模拟、高精度等已有训练记录的节点不再显示为「未学习」；用户可从节点页追溯结论对应的题目。

### 第二阶段：掌握度模型与人工校准

目标：让系统给出可解释的个人能力建议。

- 实现独立的掌握度规则模块，输出状态、证据、建议动作与置信度。
- 增加队员自评、教练确认、权限和审计记录。
- 增加低置信度与证据冲突提示。
- 在成员主页提供个人能力画像，在团队页展示覆盖分布而非简单排名。

### 第三阶段：诊断与每日计划

目标：让网站主动减少队员的选题成本。

- 为节点配置或自动挑选诊断题。
- 建立每日推荐排序：复习、补缺、诊断、巩固、进阶。
- 支持个人周目标和完成反馈。
- 在站内与 QQ 机器人中支持「今天练什么」「为什么推荐这题」。

### 第四阶段：团队训练运营

- 团队知识点覆盖图、薄弱点聚合和成员能力差异视图。
- 训练任务、阶段测验、小组赛与赛后复盘模板。
- 发布后状态通知、Worker 健康检查和结构化运行日志。

## 数据与技术约束

- `logs/` 仍是训练事实的唯一来源；能力状态、自评和确认应与原始日志区分保存，并可追踪。
- 第一阶段优先在 `scripts/generate-data.js` 生成聚合 JSON，浏览器只消费构建产物。
- 新能力数据需要共享 Schema 与迁移策略，避免前端、Worker、生成脚本分别解释字段。
- 聚合结果必须保存可追溯的题目 ID，所有结论均可跳转至具体记录。
- 掌握度规则应是有单元测试的纯函数模块，不能散落在渲染代码中。
- AI 的总结或推荐理由不得作为掌握度事实，只能解释现有证据或提出建议。

## 衡量方式

- 队员是否能在打开首页后一分钟内开始一道训练题。
- 每周来自系统推荐的训练比例、推荐题完成率与复习完成率。
- 队员更新自评、完成诊断题和处理待复习题的比例。
- 题单外训练被归属到知识点的比例，以及人工校准频率。
- 教练是否能通过团队视图定位薄弱专题，而不再手工汇总。

不将累计题数、单一掌握分数或成员排名作为核心成功指标。

## 当前优先级

下一项开发工作是「第一阶段：训练证据可见化」。它复用已有日志与标签体系，风险最低，能立即修正题单外训练被忽略的问题；完成后再引入掌握度规则、自评和诊断题。
