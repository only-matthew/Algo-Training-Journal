# 产品：个人训练闭环

版本：2026-09-29。本文是当前产品方向；当前工作区实现与线上状态的边界见 [SPECIFICATION.md](SPECIFICATION.md)，审计证据见 [Audit/PRODUCT-AUDIT.md](Audit/PRODUCT-AUDIT.md)，审计报告与修复记录见 [Audit/AUDIT-2026-10-02.md](Audit/AUDIT-2026-10-02.md)。

## 服务谁，解决什么

服务小队成员的自主算法训练。成员能够选一道值得做的题，记录这次训练的结果与关键卡点，在合适的时候重做，并回看自己的变化。共享日志和同题记录帮助交流，但个人训练收益是主线。训练可以按一天、一次练习或一场比赛发生，不要求每日打卡。

核心流程：**选题 → 做题 → 记录结果与一句有效复盘 → 形成复习安排 → 重做并留下新证据**。一次记录允许多题；同题的多次尝试应能看出前后变化。记录本身不是终点。

## 当前基线与缺口

2026-09-27 的全量日志快照有 3 名成员、157 个成员记录日、194 条题目记录、127 道唯一题；题单命中 141/2857（4.9%），只有 6/194 条处于待复习状态，42/194 条心得为空或占位。数字来自仓库源数据反推，并非页面访问或按钮点击量；过期后必须重新计算。[原始审计](archive/2026-09-28-pre-rewrite/PRODUCT-AUDIT.md)保留统计方法。

已发布的站点能提交与查看日志，展示复习队列、知识地图、题目详情和个人统计；复习状态可以单题修改。当前工作区新增默认复习建议、个人清单、同题重做历史与可复算的周期使用报告，发布前不能当作线上能力。现有 `training/` v2 后端没有生产前端消费者，不能当作已交付的训练工作台。

## 本阶段要交付

按下面顺序推进，每一步都应有可观察结果：

1. **让记录可信**：空心得保持为空；展示、导出和搜索不把“未填写”当内容。现存占位数据须先备份、再按明确规则清理。提交时提供简短复盘提示，但不强迫写长文。
2. **让复习队列有来源**：有失误，或完成结果为提示后、看题解后、未完成的记录，表单直接安排三天后复习；用户可以覆盖为不安排、超纲待做或另定日期。超纲待做只用于未完成题，不进入近期复习队列。老记录不静默改写。
3. **让选题有边界**：为当前阶段提供成员可自行维护的 20–30 题清单，展示其可完成进度。完整课程库保留为检索与参考目录，不再用其总量代表个人目标。
4. **让重做留下证据**：在同题详情中可看到每次尝试日期、结果、卡点与复盘，复习动作能进入新一次尝试。先用现有日志模型验证需求，再决定是否恢复 v2 事件存储。
5. **让效果可衡量**：从源日志生成可复算、带时间窗的周期报告；如果要采集按钮或服务调用事件，先明确最小字段、保留期和退出方式。

发布顺序以依赖关系为准；本列表不承诺具体日期。前两项优先于新平台解析、题单来源、标签扩张和外观扩展。

## 成功如何判断

| 指标 | 定义与观察方法 | 基线 | 本阶段验收方向 |
| --- | --- | --- | --- |
| 非占位心得占比 | 新记录心得不是空白或占位；另人工抽样内容质量 | 2026-09-27 快照为 152/194，包含短句，不等于有效复盘 | 占位写入为 0；真实心得占比逐期报告，不为冲数字强迫填写 |
| 复习进入率 | 有复习信号的新记录中，实际进入待复习队列的比例 | 历史总体待复习 6/194；无法当作信号组基线 | 默认规则上线后可计算，且用户覆盖权有效 |
| 重做完成率 | 到期题中，有后续尝试证据的题目比例 | 历史快照无法可靠计算 | 当前工作区报告可按同成员、同题号与日期估算；发布后首次测量 |
| 个人清单进展 | 成员自选题中有完成记录的唯一题占比 | 历史快照无个人清单 | 当前工作区有明确分母与完成证据；发布后观察使用 |
| 使用节奏 | 每周有记录的训练场次及每场题数 | 历史以“成员·日”统计，场次不可直接换算 | 同时展示估算场次与天数，不以连续打卡考核 |

报告须注明源数据、时间窗、去重规则和不可测项目；不做成员排名、逾期问责或强制通知。

## 范围与决策

- `curriculum/` 的完整题单、标签页、题面抓取和导出继续可用；新增来源先证明实际需求与维护成本。题面归档在原审计中为 0 次，是维护项，不是本阶段增长目标。

- `training/` v2 数据和后端接口保留、冻结；是否接入新训练流程要另做迁移与收益评审。现有区间统计模块仍是生产能力，不随 v2 冻结。
