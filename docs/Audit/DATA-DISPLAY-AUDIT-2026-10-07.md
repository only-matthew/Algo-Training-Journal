## 结论

初次审计确认 6 项缺陷：2 项 P1、4 项 P2。每项均有本机自动化复现。下方保留修复前的证据和影响；当前状态全部为**本地完成、未发布**。

| 编号 | 优先级 | 问题 | 可见影响 |
| --- | --- | --- | --- |
| D1 | P1 | 手动刷新只更新当前数据范围，未清理其他范围的旧缓存 | 首页已显示新增/修改记录，训练档案或成员页仍显示旧记录 |
| D2 | P1 | 标签页异步请求缺少路由/请求序号校验 | 地址栏是“搜索”，页面却被迟到请求覆盖成“二分” |
| D3 | P2 | 临时复习更新未应用到嵌套记录摘要 | 复习页已结束安排，标签页、知识地图或同题关联仍显示待复习 |
| D4 | P2 | 重建渲染器时未保留完整筛选状态 | 刷新或快捷操作后的自动刷新将指定成员、到期时间恢复为“全部” |
| D5 | P2 | 首页标签参数在近期记录无命中时被忽略 | 打开带标签的链接，实际显示全部近期记录，容易误认为标签有这些题 |
| D6 | P2 | 训练档案日期快捷筛选采用浏览器本地日期 | 使用非东八区浏览器时，“今天/本周/本月”与本站 UTC+8 数据日期不一致 |

## D1：首页刷新未使其他范围的缓存失效

位置：`lib/data.mjs:57–73`、`lib/data.mjs:83–90`；调用入口 `lib/application.mjs:99–124`。

复现：先加载完整训练档案和成员年度分片；模拟站点数据从 old 更新为 new；调用首页的 `ensureOverviewJournal(true)`；再次读取完整档案和该成员。

结果：首页的记录是 new，`ensureFullJournal()` 和 `ensureMemberJournal()` 仍返回 old。`reviewRevision` 仅在本标签页执行复习快捷操作时变化，无法覆盖他人提交、另一标签页编辑或新一轮站点发布。首页的强制刷新不清除 `fullJournal`、`manifest` 和已有的分片缓存。

建议：定义统一的刷新/缓存失效入口，刷新后让其他范围重新读取；同时防止刷新前尚未完成的请求把旧结果重新写回缓存。以“旧缓存已加载 → 远端变化 → 刷新首页 → 再进档案/成员页”为验收用例。

## D2：迟到的标签请求覆盖新路由

位置：`lib/catalog-renderer.mjs:123–158`。

复现：进入标签索引，通过 SPA 切换到“二分”；挂起 `data/tags/二分.json`；再切换到“搜索”并等待其内容显示；释放“二分”的请求。

结果：地址保持 `/tags/搜索/`，`#tag-page-title` 变回“二分”，其内容和 `data-tag` 也随旧请求覆盖。知识地图的节点加载也缺少类似校验，代码上存在同类风险；本轮直接复现的是标签页，不把知识地图另计为已复现缺陷。

建议：每次导航分配请求序号，提交内容、标题和错误状态前同时核验序号与目标路由。题目详情页已有 `problemDetailSequence` 防护，可沿用这一思路。

## D3：复习状态更新只覆盖顶层记录

位置：`lib/review-overrides.mjs:57–77`。

复现：用 `rememberReviewChange` 将一条记录从 todo 改为 archived；对相同的旧记录分别加载 `logs`、标签 `records`、题目 `related`、知识地图 `node.relatedRecords` 和 `problems[].doneBy`。

结果：`logs` 更新为 archived，另外四种结构仍保留 todo。生成脚本确实使用这些结构发布记录摘要：标签为 `records`，题目详情为 `related`，节点关联记录为 `node.relatedRecords`，参考题的成员记录为 `problems[].doneBy`。这些记录的身份字段足以应用更新，但目前加载层没有遍历它们。

建议：为这些已知结构统一应用记录更新。仅清理缓存不足以解决此问题，因为 Git 写入后、站点下一轮发布前，重新请求得到的仍是旧生成数据。验收应覆盖跨页面的状态徽章，而不只检查首页队列。

## D4：刷新丢失筛选条件

位置：`lib/renderer.mjs:735–739`、`lib/renderer.mjs:953–966`。

复现：进入复习页，成员选“廖夏”、到期时间选“未来到期”，再点击账户菜单中的刷新。

结果：`#review-member` 和 `#review-due` 均恢复为 all。渲染器保存了分析页的成员和起止日期，但没有保存复习页筛选；重新填充 select 和重写到期选项会丢掉当前选择。复习快捷操作会触发同一刷新链路，也会发生该行为。分析页的来源、难度、标签同样通过该选项重建函数初始化，需在修复验收中一并覆盖。

建议：刷新前保存完整的筛选状态，数据更新后仅在原选项已不存在时回退；保留搜索词、成员、状态、标签、难度、到期条件和首页成员选择。

## D5：无近期命中的标签被静默忽略

位置：`lib/renderer.mjs:947–951`。

复现：访问 `/?tag=没有近期记录的标签`。

结果：URL 保留标签参数，但页面显示 4 条无关的近期记录，标签筛选激活“全部”。`activeTagFilter` 只有在近期 `tagCounts` 中存在该标签时才设置，因此真实存在但只有旧记录的标签也会进入这一分支。

建议：保留用户请求的标签，近期无匹配时显示空状态，并给出查看完整训练档案的入口。首页只展示近 30 天本身是现有范围设计，本项问题是忽略筛选后显示了不符合请求的记录。

## D6：分析日期预设使用浏览器时区

位置：`lib/renderer.mjs:1016–1033`。

复现：浏览器时区设为 `America/Los_Angeles`，时间设为北京时间 `2026-10-08 00:30`；在训练档案中打开“统计分析”，点击“今天”。

结果：起止日期都设置为 `2026-10-07`，而本站 UTC+8 的当天为 `2026-10-08`。`startOfToday` 使用本地 getFullYear/getMonth/getDate，而没有使用 `todayUtc8`。本周、本月也从同一基准计算，跨周或跨月时会选错区间。热力图也使用本地当前日期，这一关联风险本轮仅做静态确认，没有单独计数。

建议：以 UTC+8 日历日计算分析预设，日期加减采用已有的日期字符串工具，避免浏览器时区和夏令时改变业务日期。QQ 凌晨 4 点换日是用户明确确认的设计，不属于本项，也不建议修改。
