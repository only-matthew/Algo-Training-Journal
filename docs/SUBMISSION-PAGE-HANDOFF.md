# 提交表单独立页面：交接文档

更新时间：2026-09-25。状态：已实施并进入维护。

## 当前实现

提交表单已经从弹窗迁移到可直接访问的 `/submit/` 页面。首页“提交 / 修改记录”和历史编辑入口都进入该页面；日期使用 `?date=YYYY-MM-DD`，题目定位使用 `problem=<稳定记录 ID>`。

页面沿用现有应用壳和淡绿山水视觉：

- 左侧为日期、题目目录、题数上限和草稿状态。
- 中央为日期与导入工具栏、多题编辑卡及吸底保存栏。
- 右侧为记录提示和装饰引言；空间不足时隐藏。
- 小于 900px 后目录和编辑区转为单栏，底部保存栏为移动导航预留空间。

业务仍由 `lib/form.mjs` 的同一套状态和保存逻辑驱动，没有建立第二份表单模型。每题最多保留题名、题号、平台、难度、标签、完成结果、掌握自评、复习安排、错题标记、题面、心得、代码、附件与 AI 辅助等原有能力。

## 2026-09-25 布局修复

复习设置的四个字段依次为“掌握自评、复习安排、错题标记、复习日期”。旧弹窗样式曾把 `.review-due-group` 固定到第 3 列；当第 3 列已有错题标记时，日期会被网格自动排到下一行，形成大块不均衡留白。

当前规则在 `.submission-page.journal-editor .review-settings` 作用域内将日期恢复为自动定位：

| 视口 | 排列 |
| --- | --- |
| 1440px / 1024px | 四项同排 |
| 800px | 两列两行；错题标记与复习日期同排 |
| 390px | 单列顺序排列 |

`scripts/smoke-submission-page.mjs` 会主动展开复习设置，检查字段位置、横向溢出和页面脚本错误，并在 `artifacts/` 生成四个宽度的截图。

## 必须保持的约束

- 每日最多 15 题，字段与总请求限额继续读取 `LOG_LIMITS`，不得在界面里另写一套数值。
- 完成结果、掌握自评、复习安排和错题标记彼此独立；导入或历史缺字段不能默认推断为独立完成。
- 草稿按账号和日期隔离；切号、切日期及迟到响应不能串数据。
- 保存仍是整日条件写入，必须携带已读取的版本；冲突时保留本地输入，不能静默覆盖。
- 题面 PDF 与抓取图片继续走 v2 multipart 保存链路；普通文本草稿不能假装已保存附件字节。
- 生成目录 `site/` 不直接编辑，先改源文件再执行构建。
- 新样式继续限制在提交页作用域，避免影响首页、分析、复习、知识地图、标签和题目详情。

## 后续维护重点

修改复习设置时同时检查条件显示的“复习日期”，避免只测试默认隐藏状态。调整通用 `.journal-editor` 样式时，应确认它不会覆盖更具体的 `.submission-page.journal-editor` 规则。涉及布局的改动至少复跑四个既定宽度，并检查吸底保存栏没有遮挡当前输入区域。
