# 题面归档与 AI 元数据补全：设计方案

日期：2026-09-15 · 状态：设计完成，尚未编码。接口和验收以 [专项技术规格](PROBLEM-ENRICHMENT-SPECIFICATION.md) 为准。

## 1. 要解决的问题

比赛题经常缺少难度、算法标签和可读题面。用户需要保留 PDF 原题，在免费网页版 LLM 中分析，再将结构化结果填回记录。Codeforces 导入还需要补上题面抓取。

本期目标是一条可人工控制的闭环：**记录题目 → 保存原题 → 获取分析 → 预览并应用元数据 → 保存记录**。不接付费模型 API，不建设聊天系统，不要求复制受限的题面能被自动解析。

## 3. 固定产品决策

### 3.1 原题、摘要、分析分开

- `description` 继续表示可阅读的题目描述。自动抓取的完整 Markdown 可填入空描述，但不能覆盖已有个人整理。
- PDF 是原题附件，可与 description 并存；不用 OCR 文本替代原文件。
- AI 题意摘要、算法理由、复杂度和估计难度属于分析结果，独立保存。应用时可选择用摘要填写空描述。
- AI 不填写代码、个人心得、是否 AC、是否独立完成、复习状态或个人水平。

### 3.2 网页版 AI 的交互边界

默认入口为 [DeepSeek 网页版](https://chat.deepseek.com)。按钮名为“复制提示词并打开 DeepSeek”，另有“仅复制提示词”。提示词可用于其他网页版模型，解析协议与模型品牌无关。

站点只复制文本并打开固定 HTTPS 地址。用户自行登录、粘贴提示词、上传 PDF 或原始截图、提交分析，再复制 JSON 回站。不会把 PDF 自动发送给第三方，不尝试跨域读取回答，不通过 URL 填充提示词或携带题目正文。

截至本次核查，直接读取 DeepSeek 页面返回 403，未验证当前登录后 PDF、图片识别能力与额度。设计不承诺“免费无限使用”或“扫描 PDF 一定可识别”。若当前网页版不能读扫描件，提示用户上传清晰截图或补充关键文字。图片本期可在外部模型中使用；站内持久化只支持 PDF，图片转 PDF、站内 OCR 留到后续。

### 3.3 难度与标签

采用现有 CF Rating 尺度，AI 返回区间、建议值、理由和自报置信程度；界面明确标“AI 估计”。置信程度不表示经校准的概率。

官方 Rating、已有人工值默认保留。AI 建议只默认勾选空字段；用户可在差异预览中显式选择替换非官方值。官方 Rating 的替换不属于 AI 回填操作。旧记录来源未知，不猜测为官方。

用户明确应用估计值后，写入现有 `difficultyRating` 并保留 `ai-estimate` 来源，沿用既有统计规则；因此可能影响难度统计与活力计算，预览中说明这一具体影响。未应用的建议不参与统计。本期不重写活力算法。

标签经现有别名映射归一化，默认与已有标签取并集，超过 10 个由用户删选；不静默截断。无法匹配站内标签的词列为待处理建议，不自动创建知识树节点。

### 3.4 PDF 存储选择

首期沿用 Git：每題最多 1 份 PDF，每文件最多 5 MiB，每次整日保存新增文件合计最多 10 MiB。以上是本项目主动设定的限额，不是平台服务上限声明。整本比赛册可作为该题附件，并填写题号和页码范围；本期不做跨题共享附件库。

选择 Git 的理由是与日志一次提交、静态发布和备份保持一致，不增加对象存储绑定和孤儿上传清理机制。代价是二进制版本长期增长。后续有大量整册 PDF 时另立对象存储迁移设计，不在此次引入双写。

上传控件注明“随记录公开保存”。删除只表示当前版本移除引用和文件，不表示清除 Git 历史。PDF 默认提供打开/下载入口，不自动嵌入页面或加入离线预缓存。

## 4. 用户流程

### 4.1 手动比赛题／扫描题面

1. 新增题目，填平台、题号或题名；保留现有最小记录要求。
2. 在“题目描述”附近添加 PDF，显示文件名、大小、选填页码和“待随记录保存”。支持替换、移除、下载已有附件。
3. 展开“AI 补全”，点击复制提示词并打开 DeepSeek。提示词含本题身份、已有元数据、描述和指定页码，提醒上传附件。
4. 返回后将 JSON 粘贴到“分析结果”，点击“校验并预览”。展示字段的当前值、建议值、来源和选择框。
5. 点击“应用到本题”，只修改当前表单；可继续编辑。点击原有保存按钮后才写入仓库。

多题表单中，每题有自己的分析请求标识；不能按数组顺序回填。更换题号或题面后，旧结果提示过期，重新生成提示词。

### 4.2 Codeforces 导入

1. 保留当前 AC 列表获取流程，先显示题名和已有元数据。
2. 用户勾选添加后，对所选题发起题面补全，最多同时 2 个请求；列表不等待所有题面完成才可使用。
3. 成功则将完整题面填入空描述；已有描述时提供预览替换。每题显示独立状态，抓取失败不撤销导入结果。
4. 详情编辑时支持“重新抓取题面”；旧记录不会在浏览页面时批量抓取或自动提交。
5. 被拦截、仅 PDF、非公开 Gym 或解析失败时，保留原题链接并提供 PDF/AI 入口。不得把登录页或验证码保存为描述。

### 4.3 状态与错误反馈

| 情况 | 用户可见反馈和恢复动作 |
| --- | --- |
| 剪贴板失败 | 展示可选中的完整提示词和独立打开链接，不宣称已复制 |
| 新窗口被阻止 | 复制状态单独显示，提供再次打开链接 |
| PDF 超限或格式不符 | 保留旧附件，显示具体限制；允许重新选择 |
| JSON 错误 | 指出字段与原因，保留粘贴文本和原表单 |
| 多题 JSON／题目身份不匹配 | 拒绝应用，要求生成对应题目的结果 |
| AI 无法读取图片 | 显示缺失信息；保留 null 难度，不造默认值 |
| 重新加载草稿 | 文本恢复；附件恢复状态单独显示，绝不假装文件仍在 |
| 保存冲突或失败 | 保留全部草稿、待上传文件和预览，不显示已归档 |
| 已保存但静态页面未发布 | 显示已保存、发布中；本人可读取最新附件 |

## 5. 界面组织

使用既有表单布局、按钮、字体和主题。题面区域先显示描述，再显示紧凑附件行；“AI 补全”默认折叠，避免每道题都增加一大块输入区。差异预览在本题内展开，不额外弹窗。

桌面用当前值/建议值对照，窄屏按字段上下排列。状态区域使用 `role=status`；校验失败聚焦错误摘要并关联具体字段。按钮文案区分“应用到表单”和“保存记录”。详情页把 AI 分析独立折叠展示，避免将解法混入原题正文。

## 6. 实施顺序与交接

1. P1：Schema、附件与来源字段、二进制保存、条件事务、兼容旧记录；先确保新增字段不会丢失。
2. P2：PDF 选择/恢复、静态发布与详情下载，完成保存闭环。
3. P3：提示词协议、JSON 验证、差异预览和回填。
4. P4：Codeforces 按题抓取与局部失败降级。
5. P5：执行专项验收与项目回归，更新交接状态；部署前验证 Worker 实际网络环境。
